# Сверка REST API с ТЗ «Чудо Обувь»

Этот проект реализует backend REST API. Он не заменяет графический интерфейс, ER-диаграмму, импорт исходных Excel-файлов и артефакты сдачи, которые отдельно требуются ТЗ.

## База данных и модели

- [x] PostgreSQL через SQLModel ORM; CRUD без ручного SQL.
- [x] Основные таблицы: `roles`, `users`, `products`, `sizes`, `stock_items`, `orders`, `order_items`.
- [x] Первичные и внешние ключи.
- [x] Уникальный логин пользователя и уникальная пара товара/размера.
- [x] Ограничения на цену и неотрицательные остатки; количество позиции заказа должно быть положительным.
- [x] Цена позиции заказа хранится отдельно от текущей цены товара.
- [ ] Автоматический импорт `Products_import.xlsx`, `Sizes_import.xlsx`, `Stock_Items_import.xlsx`, `Orders_import.xlsx`, `Users_import.xlsx`.
- [ ] ER-диаграмма PDF.

## Каталог

- [x] Получение каталога из БД.
- [x] Категория, название, производитель, состав, описание, изображение и цена.
- [x] Общий остаток по всем размерам и признак `low_stock` при остатке не более 3.
- [x] Скидка 25%, если за предыдущий календарный месяц не было заказов; базовая цена не изменяется.
- [x] Поиск без учёта регистра по названию и описанию.
- [x] Фильтрация по категории и сортировка по цене; параметры можно сочетать.
- [x] Получение размерного ряда и остатков по размерам.
- [x] Менеджер и администратор могут добавлять, изменять и удалять карточки товара.
- [x] Менеджер и администратор могут устанавливать остаток товара для размера.
- [ ] `picture.png` как fallback изображения. Это поведение клиента/интерфейса; API отдаёт `image_path`, а интерфейс должен подставлять заглушку при отсутствии/ошибке изображения.
- [ ] Макет и визуальное оформление каталога: REST API не содержит пользовательского интерфейса.

## Авторизация и роли

- [x] Вход только по логину без пароля, как требует учебное ТЗ.
- [x] После входа возвращается пользователь и роль; остальные защищённые маршруты требуют Bearer-токен.
- [x] Обычный пользователь может создать заказ для себя и видеть только собственные заказы.
- [x] Менеджер может работать с карточками товаров и остатками; по исходному ТЗ также может просматривать, создавать и удалять заказы.
- [x] Администратор может работать с товарами и остатками, видеть все заказы, менять дату заказа и редактировать позиции.

## Заказы

- [x] Заказ может включать несколько товарных позиций.
- [x] Проверяется положительное количество и доступный остаток.
- [x] Остаток блокируется на время операции и уменьшается в транзакции вместе с созданием заказа.
- [x] В заказе фиксируется цена на момент оформления, включая скидку каталога, если она действует.
- [x] Пользователь видит только собственные заказы; менеджер и администратор могут просматривать все.
- [x] Менеджер и администратор могут создавать заказ для выбранного клиента и удалять заказ.
- [x] При удалении заказа или позиции остаток возвращается на склад.
- [x] Администратор может изменить дату заказа, удалить позицию и изменить количество позиции с проверкой остатка.
- [ ] Подтверждающее диалоговое окно при удалении. Это задача клиентского интерфейса; API выполняет удаление только после явного DELETE-запроса.

## Осталось для полного комплекта сдачи

1. Реализовать импорт исходных XLSX-файлов и загрузить исходные данные.
2. Проверить работу на PostgreSQL с реальными импортированными данными и проверить сценарии ролей.
3. Подготовить ER-диаграмму в PDF.
4. При необходимости реализовать frontend: заглушку `picture.png`, визуальные уведомления, подтверждение удаления и оформление по руководству стиля.
5. При необходимости добавить тесты и инструкции для демонстрации проекта.

## Ограничение авторизации из ТЗ

Поскольку ТЗ требует вход только по логину, любой человек, знающий логин, может получить токен этого пользователя. Это не подходит для реальной системы, но сохранено как требование учебного задания.


## Импорт исходных данных

- [ ] `import_data/Users_import.xlsx` загружает пользователей и роли.
- [ ] `import_data/Products_import.xlsx` загружает каталог и связи категорий/подкатегорий.
- [ ] `import_data/Sizes_import.xlsx` загружает справочник размеров.
- [ ] `import_data/Stock_Items_import.xlsx` задаёт актуальные остатки по товару и размеру.
- [ ] `import_data/Orders_import.xlsx` загружает историю заказов с исходными ценами.
- [ ] Три товара, отсутствующие в файле каталога, восстанавливаются по истории заказов.
- [ ] История заказов не уменьшает актуальные остатки повторно.
- [ ] Скрипт запускается командой `python -m scripts.import_data`.
- [ ] Перед полной перезагрузкой данных используется явный флаг `--reset`.
