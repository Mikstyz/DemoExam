# Ручная проверка перед сдачей

Запускай backend и frontend в отдельных терминалах. Проверяй сценарии по очереди.

## Запуск и каталог

- [ ] `GET http://127.0.0.1:8000/health` возвращает `status: ok`.
- [ ] Frontend открывается без ошибок в консоли браузера.
- [ ] Каталог загружается, изображения отображаются.
- [ ] Поиск по названию и описанию работает.
- [ ] Подкатегории доступны только после выбора категории.
- [ ] Сортировка по цене меняет порядок товаров.
- [ ] У товара с общим остатком не более трёх пар отображается предупреждение.
- [ ] Скидка 25% отображается у товара без заказов в предыдущем календарном месяце.

## Пользователь и заказы

- [ ] Вход с существующим логином работает, неизвестный логин показывает понятную ошибку.
- [ ] Пользователь может выбрать размер, добавить товар в корзину и оформить заказ.
- [ ] После оформления заказа остаток уменьшается без обновления страницы.
- [ ] Пользователь видит только собственные заказы.
- [ ] Удаление заказа менеджером восстанавливает остатки.
- [ ] Недостаточный остаток не позволяет оформить заказ.

## Менеджер и администратор

- [ ] Менеджер может создать товар, загрузить изображение и добавить новый размер с остатком.
- [ ] Повторное добавление существующего размера обновляет его остаток, а не создаёт дубликат.
- [ ] Размер, состоящий только из пробелов, отклоняется с понятной ошибкой.
- [ ] При смене товара в редакторе остатки соответствуют выбранному товару.
- [ ] Нельзя привязать подкатегорию к другой категории.
- [ ] Администратор может изменить дату заказа.
- [ ] Изменение количества позиции корректно меняет складской остаток.
- [ ] Удаление позиции заказа восстанавливает складской остаток.
- [ ] Попытка удалить товар из истории заказов отклоняется, чтобы не нарушить историю.

## Что помнить

Авторизация через `X-User-ID` не является безопасной для публичного сервера: пользователь может подменить ID. Для учебной сдачи это соответствует упрощённой схеме без паролей и JWT, но не предназначено для реального магазина.
